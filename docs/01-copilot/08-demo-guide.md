## 概念讲解判断

### 需要展开讲解的概念

| 概念 | 讲解方式 | 何时插入 |
|------|---------|---------|
| **什么是 AI 编程助手** | 比喻：像有一个坐在旁边的资深同事，你描述需求他帮你写 | 开场阶段 |
| **Prompt（提示词）** | 比喻：就是你和 AI 说话的方式，说清楚要什么 | 阶段 2，第一次用 Chat 时 |
| **Context（上下文）** | 比喻：AI 读不到你的心，需要你告诉它相关信息 | 阶段 4，演示 #file 引用时 |
| **Inline Suggestions（内联补全）** | 现场演示，"看，灰色虚文就是它的建议" | 阶段 1 |
| **Agent（智能体）** | 比喻：从"你问一句答一句"到"你说一个任务它自己干完" | 阶段 5，Agent 演示时 |

### 一笔带过、知道存在即可的概念

| 概念 | 简要说明 | 何时提及 |
|------|---------|---------|
| **Custom Agent** | "可以给 AI 设定角色，比如安全审查员" | 阶段 8 概览时 |
| **Skill** | "把一套操作打包成技能，需要时调用" | 阶段 8 概览时 |
| **MCP** | "让 AI 连接外部工具的协议，比如操作浏览器" | 阶段 8 概览时 |
| **Hook** | "AI 操作前后自动执行的脚本，类似 Git hook" | 不在演示中提及 |
| **Plugin** | "把上面的东西打包分发给团队" | 不在演示中提及 |
| **BYOK** | "可以不用 GitHub 账号，用自己的 API Key" | 不在演示中提及 |

### 不需要提及的概念

- Agent Host Protocol、Agent Loop 内部机制
- Token bucket、context compaction 等内部概念
- chatLanguageModels.json 配置细节
- Dev Container 中的 MCP 配置

## 详细演示步骤

### 阶段 0：开场（5 分钟）

**目标**：让听众理解 Copilot 是什么，建立信心。

**讲解要点**：
1. "今天给大家介绍一个工具，它能帮你写代码、改代码、查问题——即使你不是程序员"
2. VS Code Copilot = VS Code 编辑器里内置的 AI 助手
3. 它能做的三件事：你打字时帮你补全 / 你用自然语言问它问题 / 你描述一个任务它自主完成
4. 强调：你不需要懂编程也能用

**实机准备**：提前打开 VS Code，确保已登录 Copilot，打开一个 demo 项目文件夹

---

### 阶段 1：内联补全演示（10 分钟）

**目标**：展示最基础的交互——打字时 AI 自动补全。

**Step 1.1：基本补全**
1. 新建 `demo.py` 文件
2. 输入 `def calculate_area(width, height):`
3. 停顿——灰色虚文显示函数体建议
4. 讲解："看，灰色文字就是它的建议"
5. 按 `Tab` 接受

**Step 1.2：多个建议切换**
1. 输入 `def send_email(to, subject, body):`
2. 等待建议出现
3. 按 `Alt+]` 切换下一个建议，`Alt+[` 切回
4. 讲解："同一个位置它可能有多个建议，可以切换看"

**Step 1.3：注释驱动生成**
1. 输入注释：`# 批量重命名文件夹中的图片，加前缀 "texture_"`
2. 按 Enter 换行
3. Copilot 建议整段代码
4. 讲解："你只要用注释说清楚你要什么，它就能帮你生成"

**Step 1.4：针对美术/建模的场景**
1. 新建 `rename_textures.py`
2. 输入注释：`# 把文件夹里所有 .png 图片缩放到 512x512`
3. 让 Copilot 补全
4. 讲解："即使你不懂 Python，也能用这种方式生成工具脚本"

**互动**：让一个志愿者说出功能需求，现场用注释生成代码

---

### 阶段 2：Chat 聊天演示（10 分钟）

**目标**：展示自然语言对话——提问、解释、探索。

**Step 2.1：打开 Chat**
1. 按 `⌃⌘I`（Mac）/ `Ctrl+Alt+I`（Win）打开 Chat 面板
2. 讲解："这就是聊天面板，和 ChatGPT 类似，但它能看到你的代码"

**Step 2.2：解释代码**
1. 打开项目中一个稍微复杂的文件
2. 在 Chat 中输入：`解释一下这个文件是做什么的`
3. AI 分析文件并用自然语言解释
4. 讲解："如果你接手了别人的代码，这个功能非常有用"

**Step 2.3：提问技术问题**
1. 输入：`什么是 CORS？为什么我的网页请求会报 CORS 错误？`
2. AI 给出解释
3. 讲解："任何技术问题都可以直接问，不需要去 Google 翻英文文档"

**Step 2.4：生成代码**
1. 输入：`帮我写一个 Python 脚本，把一个文件夹里所有 .json 文件合并成一个`
2. AI 生成代码
3. 讲解："它可以直接在编辑器里创建文件"

**互动**：让大家说说自己的工作中有什么重复性任务，现场让 AI 写脚本

---

### 阶段 3：Inline Chat 就地修改演示（10 分钟）

**目标**：展示不离开编辑器、就地修改代码的方式。

**Step 3.1：基本 Inline Chat**
1. 打开一个代码文件
2. 选中一段代码
3. 按 `⌘I`（Mac）/ `Ctrl+I`（Win）
4. 讲解："看，在选中的代码旁边弹出了一个小输入框"
5. 输入：`把这段代码的变量名改成英文`
6. 展示 diff，用 Keep 或 Undo

**Step 3.2：选中代码改写**
1. 选中一个函数
2. 按 `⌘I`
3. 输入：`给这个函数添加错误处理，用 try/catch`
4. 展示 diff 视图
5. 讲解："红色是删除的，绿色是新增的，和 Git 的 diff 一样"

**Step 3.3：终端 Inline Chat**
1. 打开终端 `⌃\``（Mac: `⌃\`` ）
2. 按 `⌘I`（Mac）/ `Ctrl+I`（Win）
3. 输入：`怎么查找当前目录下所有大于 10MB 的文件？`
4. AI 生成命令
5. 按 `⌘Enter`（Mac）/ `Ctrl+Enter`（Win）运行
6. 讲解："终端里也能用，不会写命令直接用中文问"

**Step 3.4：美术场景演示**
1. 打开一个配置/文本文件
2. 选中一段
3. 按 `⌘I`
4. 输入：`把这段配置里的分辨率从 1024 改成 2048，同时更新相关的引用`
5. 展示改动

---

### 阶段 4：上下文引用演示（10 分钟）

**目标**：展示如何给 AI 提供正确的上下文——这是用好 Copilot 的关键。

**Step 4.1：#file 引用**
1. 在 Chat 中输入：`解释 #utils.py 中的每个函数`
2. 讲解："# 号后会弹出文件列表，选一个文件让 AI 去看"

**Step 4.2：#codebase 全局搜索**
1. 输入：`认证逻辑是在哪个文件里实现的 #codebase`
2. AI 搜索整个项目找到相关代码
3. 讲解："#codebase 让 AI 在整个项目中搜索，不用你自己找"

**Step 4.3：拖拽文件**
1. 从侧边栏文件树拖一个文件到 Chat 面板
2. 讲解："也可以直接拖文件过去"

**Step 4.4：#changes 引用 Git 变更**
1. 做一些代码修改（不保存）
2. 输入：`给 #changes 生成一段提交说明`
3. AI 分析你改了什么，生成 commit message

**Step 4.5：图片作为上下文**
1. 截一张网页设计图（或用准备好的图片）
2. 拖到 Chat 面板
3. 输入：`按照这张图用 HTML 和 CSS 实现这个布局`
4. AI 根据图片生成代码
5. 讲解："设计师给的设计图，直接让 AI 转成代码"

---

### 阶段 5：Agent 模式演示（10 分钟）

**目标**：展示 Agent 自主完成多步任务——这是最令人印象深刻的功能。

**Step 5.1：切换到 Agent 模式**
1. 在 Chat 面板的输入框上方，找到 Agent 选择器
2. 从 "Ask" 切换到 "Agent"
3. 讲解："Ask 是只读问答，Agent 是可以改文件的"

**Step 5.2：用 Plan 先规划**
1. 切换到 "Plan" 模式
2. 输入：`帮我给这个项目添加一个用户注册页面，包含表单验证`
3. Plan Agent 生成实施计划
4. 讲解："先规划再执行，这是最佳实践"

**Step 5.3：切换到 Agent 执行**
1. 审查计划后，切换到 "Agent" 模式
2. 输入：`按照上面的计划实施`
3. Agent 自主工作：读文件 → 改代码 → 可能运行命令
4. 讲解："看，它在自己搜索、自己读文件、自己改代码。你只需要看它做的对不对"

**Step 5.4：审查改动**
1. Agent 完成后，展示改动列表
2. 逐个查看 diff
3. 讲解："一定要审查！AI 也会犯错。用 Keep 接受、Undo 拒绝"

**Step 5.5：权限控制**
1. 讲解："如果你担心它乱改，可以设置需要确认每个操作"

**互动**：让大家提一个功能需求，现场用 Agent 模式实现

---

### 阶段 6：Custom Instructions 演示（10 分钟）

**目标**：展示如何让 AI 懂你的项目规范。

**Step 6.1：用 /init 自动生成**
1. 在 Chat 中输入：`/init`
2. AI 分析项目并生成 `.github/copilot-instructions.md`
3. 打开生成的文件
4. 讲解："AI 自动分析了你的项目，生成了规范文件"

**Step 6.2：手动创建**
1. 在项目根目录创建 `.github/copilot-instructions.md`
2. 写入一些规则（4 空格缩进 / 函数名用英文小写 / 注释用中文等）
3. 保存
4. 在 Chat 中提问，观察 AI 是否遵循了规则

**Step 6.3：文件级指令**
1. 创建 `.github/instructions/python.instructions.md`
2. 写入 applyTo: "**/*.py" 的规则
3. 讲解："不同文件类型可以有不同的规则"

**对比演示**：不加 instructions 时 vs 加了之后，同样的 prompt 生成结果对比

---

### 阶段 7：Prompt Files 演示（10 分钟）

**目标**：展示可复用的任务模板。

**Step 7.1：创建 Prompt File**
1. 创建 `.github/prompts/gen-test.prompt.md`
2. 写入内容（生成单元测试的模板 + 变量）
3. 保存

**Step 7.2：使用 Prompt File**
1. 在 Chat 中输入 `/gen-test`
2. AI 提示输入文件路径
3. Agent 开始生成测试
4. 讲解："以后写测试只要输入一个斜杠命令就行"

**Step 7.3：更多示例**
1. 创建代码审查模板、修复编码问题模板
2. 讲解："任何重复性的任务都可以做成 Prompt File"

---

### 阶段 8：概念讲解（5 分钟）

用比喻和一句话解释帮大家理解概念：

**Prompt（提示词）**：就是你对 AI 说的那句话。比喻：像点菜——"来个宫保鸡丁" vs "来个不辣的宫保鸡丁，少放油，花生多放点"，后者更明确。

**Context（上下文）**：AI 需要知道的背景信息。比喻：你让同事改 bug，但不告诉他哪个文件，他改不了。

**Agent（智能体）**：从"你问一句答一句"升级到"你说一个任务，它自己干完"。比喻：Chat 像你问同事问题，Agent 像你给实习生布置任务让他自己去搞定。

**Custom Agent**：给 AI 设定特定角色。比喻：就像团队里有不同岗位的人。

**Skill（技能）**：把一套操作步骤打包。比喻：像把一个 SOP 写好，谁需要就按流程走。

**MCP**：让 AI 连接外部工具的标准。比喻：给 AI 装了"手"，能操作其他软件。

**Instructions（指令）**：项目规范文件。比喻：贴在工位上的备忘录，AI 每次都看。

---

### 阶段 9：互动与 Q&A（10 分钟）

**预设问题**：

1. "我不是程序员，能用到 Copilot 吗？" → 展示批量处理图片的例子
2. "AI 生成的代码可靠吗？" → 不可靠，必须审查。AI 是助手不是替代品
3. "Copilot 会泄露我的代码吗？" → 有隐私模式设置，企业版不会用你的代码训练模型
4. "需要什么配置才能跑？" → 能跑 VS Code 的电脑和网络即可
5. "和 ChatGPT 有什么区别？" → Copilot 能直接读你的项目文件、改代码、运行命令
6. "免费额度够用吗？" → 免费计划含每月限额。日常轻度使用够用

## 讲解节奏建议

1. **先看效果再讲概念**：每个阶段先展示"它能做什么"，再说"这是什么"
2. **多用比喻少用术语**：对美术/建模同事，"AI 助手"比"LLM"更容易理解
3. **每个阶段留 1-2 分钟互动**：让大家提需求现场做
4. **别怕说"我也不确定"**：遇到不熟悉的领域，可以说"我们让 Copilot 来告诉我们"
5. **强调审查的重要性**：AI 会犯错，必须人审。这是反复强调的安全底线
6. **渐进式深入**：基础 → 上下文 → Agent → 定制，每步建立在前一步之上
