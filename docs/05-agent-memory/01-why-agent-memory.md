# 为什么 Agent 需要长期记忆

## 本章解决什么

先看一个每天都可能发生的小场景：上周你让 AI 帮忙整理了一整套贴图命名规范，今天开了新会话想让它继续干活，结果它完全不记得这回事，你得把规范从头到尾再讲一遍。这不是个例——**每次开新会话，AI 都会"失忆"**。本章回答三个问题：为什么会这样、长期记忆到底记住的是什么、以及用一套框架（TencentDB Agent Memory）来看，团队的 AI 应该记住哪几类东西。读完你会理解：给 AI 装"记忆"，不是存聊天记录，而是给团队沉淀一套**可复用的记忆资产**，让下一个 Agent 不用重新发明轮子（核验于 2026-08）。

---

## 痛点开场：换个会话，AI 就"失忆"

### 三个每天都在重复的场面

| 场面 | 典型例子 | 浪费在哪 |
| --- | --- | --- |
| 重复自我介绍 | "我是负责角色建模的小李，我们项目用 Maya，单位是厘米" | 每次新会话都要重新教一遍基本背景 |
| 重复讲项目背景 | "这个项目是低模风格，贴图用 PBR 流程，输出目录在 `D:/Projects/Demo/export`" | 项目约定越长，讲得越久，还容易讲漏 |
| 重复踩坑 | "上次提醒过：批量处理前必须先备份原文件" | 同一个坑换个会话又踩一遍，返工 |

> 💡 可以把每个新会话想象成**来了一个什么都不懂的新同事**：他没看过我们的项目文档，也不知道团队的规矩。你每开一个会话，就要把入职培训重讲一遍。长期记忆，就是给这位"新同事"一本他自己会写的笔记。

### 这不是 AI 笨，是它没有"长期记忆"

为什么会这样？因为大多数 AI 工具在**每次会话开始时都是"白纸一张"**：它只看得到当前这个会话里你给它的内容，会话一关，那些内容就留在那个会话里，不会自动带到下一个会话。你"讲过"和它"记得"，是两回事。

在第 3 期（Hermes）里我们讲过，Hermes 有一个像**"小笔记本"**一样的 **Memory（记忆）**，可以记住少量长期偏好。但那本笔记本是"个人便签"：记什么、怎么记，基本靠你逐条告诉它。

本期的思路往前走了一大步：记忆不只是一张便签，而是一整套**资产管理**——对话、技能、文档、代码，都能沉淀下来，由系统统一组织、按需取用。官方对这一问题的原话是：

> "项目背景讲过了，不该换个 Session 再讲。文档读过了，不该每个 Agent 从第一页重读。一套做法已经跑通，不该下次再摸索一遍。"

一句话：**凡是能让下一个 Agent 少走弯路的信息，都应该被保存、组织并复用。**

## 先澄清一个概念：记忆 ≠ 聊天记录

很多人以为"让 AI 记住"就是"把聊天记录存下来，下次接着翻"。这个理解不完整。

| | 聊天记录 | 长期记忆 |
| --- | --- | --- |
| 内容 | 完整对话原话 | 提炼后的事实、偏好、流程、结论 |
| 组织方式 | 按时间堆在一起 | 按资产分类、可检索、可共享 |
| 谁在用 | 只有当时那一个会话 | 整个团队的 Agent 都能用 |
| 类比 | 录像带 | 工作笔记 + 手册 + 资料库 |

所以长期记忆的真正价值不是"存档"，而是**让下一个 Agent 直接读档**：它不需要重看一遍录像，而是拿到一份整理好的笔记，几秒钟就能进入工作状态。官方给出的价值链条是：

> 已有信息 → 可复用记忆资产 → 更少 Turns → 更少返工 → 更稳定的结果和更高的效率

（官方基准 PersonaMem 显示：启用记忆后，Agent 在长期交互中正确理解和运用用户信息的能力从 48% 提升到 76%，相对提升约 59%——该项公开基准仅此一个，复现细节待核验。）

技术上，这套系统不追求"存下所有东西"，而是解决三个问题：**什么值得留下、谁可以使用、下一次怎样少拿但拿对**。知识也不是整库塞进上下文，而是按需调用：Agent 先"发现"有什么能力，再"调用"去读具体页面、源码或影响路径。

## 四类记忆资产：Agent 的"档案柜"

TencentDB Agent Memory 把记忆分成四类资产，我们可以把它们想象成团队档案柜里的四个抽屉。每个抽屉都回答三个问题：**是什么、记什么、帮谁省事**。

### Chat Memory（对话记忆）——"私人记事本"

- **是什么**：从对话中沉淀下来的记忆，保留偏好、事实、决策和交互历史。每个 Agent 创建时自动获得一份独立记忆。
- **记什么**：你的偏好（"贴图默认输出 JPG，质量 90"）、项目事实（"我们做低模风格"）、决策记录（"这版场景统一用 512 贴图"）。
- **帮谁省事**：所有人。下次对话不必从自我介绍开始，Agent 直接进入你的语境。

> 美术同事的例子：你说过一次"角色贴图命名用 `角色名_部位_贴图类型`"，之后每次让 Agent 帮忙整理贴图清单，它都按这个规则来，不用再解释。

### Skill（技能）——"SOP 手册"

- **是什么**：从跑通的任务里提炼出的可复用流程，附版本、资源文件、触发边界、执行步骤、验证规则。个人 Skill 默认私有，审核后可以分享给团队，再配装给其他 Agent。
- **记什么**：一套成熟做法，比如"贴图检查 SOP""场景导出检查清单""发布前上线检查"。
- **帮谁省事**：全团队。"练会一次，全队可用"——美术同事跑通的批处理流程，建模同事的 Agent 也能直接调用。

> 建模同事的例子：你花一下午理顺了一套"高模减面 → 烘焙 → 导出"流程，把它沉淀成 Skill 后，团队里任何人的 Agent 都能照着这套已验证的步骤执行，不用每个人重新摸索。

### Wiki（知识库）——"团队资料库"

- **是什么**：把产品文档、设计方案和运维手册等生成结构化的页面与链接图谱（灵感来自 Karpathy 的 "LLM Wiki" 设想）。
- **记什么**：团队已有的文档资产，组织成"页面 + 链接"的形式，方便一层层下钻。
- **帮谁省事**：需要查资料的同事。Agent 不必把整个文件目录从头读一遍，而是像查资料库一样直接检索到相关页面。

> 程序同事的例子：想让 Agent 查"项目里对文件路径的处理统一写在哪个模块"，它不必翻遍所有目录，先在 Wiki 里定位到相关页面，再下钻到细节。

### CodeGraph（代码图谱）——"代码地图"

- **是什么**：索引代码里的符号、文件、调用关系和影响路径。
- **记什么**：哪段代码被谁调用、改了会影响到哪里。
- **帮谁省事**：程序同事。Agent 改代码前先做影响分析："改了 `A` 会影响 `B` 和 `C`"，降低改崩项目的风险。

> 程序同事的例子：想重构某个工具函数，先让 Agent 查 CodeGraph 看谁在调用它、有没有依赖它的测试，再决定怎么改、改完要回归验证哪些地方。

> ⚠️ 四个抽屉不是每个团队都要立刻装满。美术、建模同事日常最常用到的是 **Chat Memory + Skill**；Wiki 和 CodeGraph 更多是文档与程序向的使用，但理解它们能帮你看懂整套系统能做什么。

### 谁可以用：记忆的可见性

档案柜里的东西不是谁都能翻。系统用四级可见性控制每份资产谁能读：

| 可见性 | 语义 |
| --- | --- |
| **private** | 只有 Owner（创建者）可读，团队管理员也不例外 |
| **team** | 团队成员可读，由 Owner / Admin 管理 |
| **restricted** | 通过 User / Role / Agent 的 ACL 精确授权 |
| **agent** | 定向配装给同团队指定 Agent |

两个对你很重要的默认值：新创建的 Chat Memory 和 Skill **默认私有**——"分享是一个明确动作，不是默认泄漏"。这意味着你可以放心先把自己的经验和偏好记下来，想清楚了再决定要不要共享给团队。

## Chat Memory 的 L0–L3 蒸馏层级

对话记忆不是"原样保存所有话"，而是像酿酒一样**层层蒸馏**。官方把蒸馏分成四级：

| 层级 | 保存什么 | 主要用途 |
| --- | --- | --- |
| **L0 Conversation** | 原始对话与完整上下文 | 核对原话、时间和来源 |
| **L1 Atom** | 从对话中提取的事实、偏好、约束与事件 | 精确召回可执行信息 |
| **L2 Scenario** | 围绕项目或场景组织的知识块 | 快速恢复一个工作场景 |
| **L3 Core / Persona** | 长期画像、稳定模式与高层认知 | 让 Agent 迅速进入用户和团队语境 |

用例子看更直观。假设你连续三天跟 Agent 聊同一个项目：

- **L0**：存下三天所有对话原话——"万一要回头核对哪句话是谁说的、什么时候说的，翻这里"。
- **L1**：提炼出事实："项目用 Maya""输出目录是 `D:/Projects/Demo/export`""不要覆盖原文件"。
- **L2**：把相关事实组织成一个场景块："角色建模工作流：单位、命名、导出"，一次恢复整个工作场景。
- **L3**：形成长期画像："这个团队做低模风格，偏好简洁步骤，效率优先"，让 Agent 迅速进入团队语境。

这套分层的妙处在**生成和召回都分层**：平时用 **L2 / L3** 快速进入语境，不用每次都翻原始记录；需要具体事实时，再通过关键词（BM25）与向量检索，把 **L1 / L0** 的精确内容取回来；对取回结果还设有条数、字数预算和超时限制，防止把上下文撑爆。各层的具体召回上限数值官方文档未给出——待核验。

## 与前面几期的衔接

| 期数 | 讲了什么 | 与本期关系 |
| --- | --- | --- |
| 第 1 期 Copilot 上下文 | **一次会话内**：怎么把当前任务讲清楚，让 AI 理解现在 | 解决"当下"——会话结束即失效 |
| 第 2 期 Skill | **复用流程**：把一套跑通的做法打包成可复用能力 | 是本期"记忆资产"里的一类（Skill），但只覆盖流程 |
| 第 3 期 Hermes Memory | 个人"小笔记本"：记少量长期偏好 | 记忆的雏形——单机、单用户、手动管理 |
| 本期 Agent 记忆 | **跨会话、跨 Agent**：对话 + 技能 + 文档 + 代码统一沉淀 | 把"小笔记本"升级为团队的"档案柜" |

一句话概括区别：**上下文管"这一次会话"够不够清楚，记忆管"下一个会话、下一个 Agent"还记不记得**。前几期教的是"让 AI 今天干好活"，本期教的是"让 AI 越用越懂你和你的团队"。

## 一句话总结

> 记忆是团队 AI 能力底座的**记忆层**：它把每次对话、每个流程、每份文档、每行代码变成可复用的资产，让 AI 从"每次重新发明轮子"变成"直接读档开工"——项目背景讲一遍就够了，跑通的做法全队都能用，踩过的坑不必再踩。
