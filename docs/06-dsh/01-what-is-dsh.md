# DSH 是什么

## 本章解决什么

用最通俗的话讲清楚三件事：DSH 到底是什么、它和其他 AI Agent 工具有什么不同、它适合做什么。读完你可以判断自己是否需要它。

## 一句话说清楚

**DeepSeek Harness（DSH）是 DeepSeek 推出的可组合 AI Agent 运行时框架。**

你可以把 DSH 理解成一个「可定制的 AI 工作台」：它不像 Copilot 那样紧贴编辑器，也不像 Hermes/Pi 那样是一个固定的终端对话程序。DSH 的核心思想是——**所有能力都是可插拔的插件**，你可以像搭积木一样，把终端、文件系统、网页搜索、子代理、工具、技能等能力按需组合成你需要的 Agent。

> 普通 AI 工具是**一盒装好的乐高套装**，打开就用但是改不了零件。
>
> DSH 是**乐高底板 + 零件箱**：你先选底板（Profile），再拼零件（能力），还能在运行时临时插一块新砖上去（动态插件）。

## DSH 的三个核心概念

DSH 有三个层层递进的概念：

### 1. Profile（配置文件）

Profile 是 DSH 的启动配置，定义了「这个 DSH 实例能做什么」。

```
dsh --profile web          # Web GUI 模式（默认，本文档的主战场）
dsh --profile headless ... # 无头模式：跑一个任务，输出结果，适合脚本化
dsh --profile tui ...      # 终端 TUI 模式（需单独安装） 
```

> 💡 本文档围绕 `dsh web` 展开——它是你日常打开浏览器用的那个界面。

### 2. Cordis 组合系统

Cordis 是 DSH 内部的能力编排引擎。每一个能力（比如「能跑 bash」「能读文件」「能搜网页」）都是一个 **插件行（plugin row）**，写在 `cordis.yml` 文件里。Profile 启动时，把这些插件行按顺序层叠起来，形成最终的能力组合。

### 3. Agent Preset（Agent 预设）

Agent Preset 决定了「当前这个 Agent 会话里，AI 有哪些工具、什么性格、什么规则」。DSH 自带四种预设：

| Preset | 中文名 | 一句话 |
| --- | --- | --- |
| **standard** | 标准模式 | 功能完整的编码 Agent，有文件、Shell、网页、技能、子代理等全套工具 |
| **cordis** | 创造模式 | 在标准模式基础上加了运行时检查和插件创作能力（本文档写作时使用的模式） |
| **code** | PTC 模式 | 在标准模式基础上用 Code Mode SDK 把多步操作合并为一段 TypeScript 程序 |
| **minimal** | 极简模式 | 只有持久 bash + 文件编辑器两个工具，最轻量 |

## DSH 和你已知的工具，有什么不同

| 维度 | DSH | Copilot | Hermes | Pi |
| --- | --- | --- | --- | --- |
| **定位** | 可组合的 Agent 框架 | 编辑器里的 AI 结对编程 | 终端里的个人 AI 助理 | 终端里的极简编程助手 |
| **运行方式** | Web GUI / TUI / headless | VS Code 插件 | CLI / TUI / 桌面应用 / Gateway | 终端 CLI |
| **能力边界** | 由 Profile + Preset 决定，可动态扩展 | 编辑、终端、MCP 工具 | 终端、文件、浏览器、记忆、技能 | 文件、终端、自定义扩展 |
| **可扩展性** | ⭐⭐⭐ 核心卖点：动态插件 + Cordis 组合 | ⭐⭐ 自定义指令、Hook、Plugin | ⭐⭐ Skill、Memory | ⭐⭐ Extension、Skill、Theme |
| **学习曲线** | 较陡（理解 Cordis 需要时间） | 平缓（基本即装即用） | 中等 | 中等 |
| **适合谁** | 想深度定制 Agent 行为的开发者 | 所有写代码的人 | 需要执行长流程任务的人 | 喜欢终端极简体验的人 |

## DSH 适合做什么

| 场景 | 适合用 DSH 吗 | 说明 |
| --- | --- | --- |
| 日常写代码、改 bug | 🟡 可以，但 Copilot 更顺手 | DSH 的强项不在编辑器集成，而在运行时定制 |
| 自动化脚本 / CI 任务 | 🟢 非常适合 | `dsh --profile headless "跑测试"` 直接输出结果 |
| 创建自定义 AI 工具 | 🟢 核心场景 | 动态插件 + Cordis 组合就是为这个设计的 |
| 多 Agent 并行协作 | 🟢 非常适合 | 子代理 + 工作流 + Ralph 迭代都是原生支持 |
| 文件批量处理 | 🟢 很适合 | 标准模式下的文件 + bash + 搜索工具足够 |
| 作为团队共享的 AI 工作台 | 🟢 优势场景 | Preset 可以复制、修改、分发，团队统一维护 |

## DSH 不能替你做什么

| 它不能替你做的事 | 为什么 |
| --- | --- |
| 判断最终产品效果是否合格 | 审美、项目标准和用户需求需要人判断 |
| 决定是否批准高风险操作（如 `danger-full-access` 模式） | DSH 有沙箱和审批机制，最终决定必须由你做 |
| 保管 API 密钥、密码等敏感信息 | 不要在任何 AI 聊天或配置里明文存储密钥 |
| 100% 保证输出正确 | AI 可能误解需求，最终验收必须由你做 |
| 替代你对 Cordis 架构的理解 | 动态插件是 trust boundary（信任边界），不是 sandbox（安全沙箱） |
