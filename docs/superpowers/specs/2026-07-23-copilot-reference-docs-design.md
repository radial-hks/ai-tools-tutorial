# VS Code Copilot 团队参考手册重构设计

## 背景

`docs/01-copilot/` 当前包含七章产品文档和一份实机演示指南，已经覆盖 Copilot 的基础交互、上下文、Agent、定制和 MCP。现有内容适合作为培训初稿，但作为团队参考手册仍有以下问题：

- 产品概念的分类维度混杂，例如把交互界面、Agent 角色和运行位置都称为“模式”或“Agent 类型”
- 基础功能、进阶参考和讲师脚本存在重复定义，后续容易产生版本漂移
- 部分绝对表述、设置默认值和模型建议容易随 VS Code 更新而失效
- 信息主要按学习顺序组织，按任务检索时需要跨多章查找
- 章节标题、正文数量和导航描述存在局部不一致

本次重构将 `01-copilot` 定位为团队参考手册。优先级依次为准确性、可检索性、可维护性和新人可读性。

## 范围

本次包含：

- 全面重构 `docs/01-copilot/` 的章节边界、文件名和导航
- 对照 2026 年 7 月的 VS Code 官方文档核验功能名称、配置方式和状态
- 更新仓库根目录入口、共享术语表和快捷键速查
- 保留讲师演示指南，但将其改为独立附录
- 修复仓库内受影响的 Markdown 链接

本次不包含：

- 扩写 `02-copilot-skills`、Hermes 或 Pi 文档
- 建立文档站点或引入静态站点生成器
- 添加容易随界面更新而过期的截图
- 为所有官方功能建立完整 API 级参考

## 信息架构

核心手册重建为七个主题章和一个讲师附录：

| 文件 | 职责 |
|------|------|
| `README.md` | 手册定位、版本基线、按任务查找、章节地图 |
| `01-overview-and-setup.md` | 产品边界、账号与额度、安装和验证 |
| `02-chat-and-inline.md` | Chat View、Agents Window、Inline Chat、Quick Chat 等交互界面 |
| `03-context-and-prompts.md` | 隐式上下文、显式引用、图片与浏览器上下文、提示和会话管理 |
| `04-agents-and-workflows.md` | Agent 会话配置维度、规划实施审查工作流和多会话协作 |
| `05-customization.md` | Instructions、Prompt Files、Skills、Custom Agents、Hooks 和 Plugins 的选择与配置 |
| `06-mcp-and-tools.md` | 内置工具、MCP 能力、安装配置、信任、沙箱和排错 |
| `07-safety-and-troubleshooting.md` | 代码审查、权限、密钥与隐私、回滚、诊断和常见问题 |
| `appendix-demo-guide.md` | 面向讲师的演示流程、准备清单和可复制 Prompt |

原文件使用 `git mv` 重命名，以保留历史。仓库内链接全部迁移到新路径。由于仓库直接渲染 Markdown，不保留旧文件占位页，避免占位内容污染搜索和导航。

## 概念模型

手册使用以下五个独立维度描述 Copilot，避免把不同概念混为一谈：

1. **交互界面**：Agents Window、Chat View、Inline Chat、Quick Chat
2. **运行位置**：本地 Agent、Copilot CLI、Cloud Agent、第三方 Agent
3. **Agent 角色**：内置 Agent、Plan、Ask，以及 Custom Agent
4. **语言模型**：驱动当前会话推理和生成的模型
5. **权限级别**：工具调用和终端命令需要何种确认

“模式”只在官方界面或历史名称必须引用时使用，并注明当前官方术语。每个概念只在其所属章节完整定义一次，其他章节通过链接引用。

## 章节模板

核心章节按需采用以下顺序，未涉及的部分可以省略：

1. 本章解决什么
2. 概念和选择矩阵
3. 操作步骤
4. 最小可复现实例
5. 风险、限制和版本状态
6. 排错入口
7. 官方参考
8. 前后章导航

内容使用中文撰写，官方英文名称在首次出现时保留。后续统一使用一个中文名称或英文名称，不为同一概念创造多个译名。

## 准确性与版本策略

- 事实基线标为“核验于 2026-07”，不暗示内容永久有效
- 官方标记为 Preview 或 Experimental 的能力在首次出现处明确标注
- 易变的界面位置优先给出 Command Palette 命令，快捷键作为补充
- 删除缺少官方依据的固定默认值、绝对承诺和供应商模型排名
- 设置项只保留完成常见任务确实需要的部分，不复制完整设置清单
- 关键功能在章末链接到对应的 VS Code 或 GitHub 官方文档
- 安全、隐私和额度信息避免自行推断；无法稳定概括时直接引导到官方政策页

## 内容迁移与去重

- 原“最佳实践”不再作为重复汇总章存在
- 提示方法和会话管理归入上下文章
- Plan→Implement→Review 归入 Agent 工作流章
- 改动审查、检查点、权限、密钥和故障处理归入安全与排错章
- 快捷键的 Copilot 专用部分放在对应功能章，共享速查仅保留跨工具的 VS Code 基础快捷键
- 术语表提供一句话定义，不复制正文教程
- 讲师附录引用核心章节中的定义，不再维护第二套概念说明

## 讲师附录

讲师附录继续服务 60 至 90 分钟的团队分享，但与核心参考内容分离。附录包含：

- 演示目标、时长和对应核心章节
- 演示前环境与备用方案
- 可重复、低风险的操作步骤
- 适合美术、建模和开发同事的任务示例
- 可直接使用的 Prompt

附录不重复解释 Agent、Context、MCP 等概念。涉及易变界面的步骤以命令名称为主，并提醒讲师在分享前按当前 VS Code 版本预演。

## 验收标准

1. `01-copilot` 首页可按“提问、修改、规划、定制、连接工具、排错”直接定位章节
2. “如何选择 Agent”“如何配置项目规范”“如何安全安装 MCP”均可在两次点击内找到答案
3. 所有仓库内 Markdown 链接指向存在的文件或标题
4. 所有章节的前后导航闭环，附录能返回首页
5. 旧文件名、旧章节名和互相冲突的术语无残留
6. JSON、YAML 和命令示例中可自动验证的部分通过语法检查
7. 关键官方链接可访问，易变事实带来源、核验日期或功能状态
8. Markdown 诊断无新增错误
9. 根目录入口、共享术语表和核心手册使用一致的章节名和术语

## 实施顺序

1. 建立新文件映射并更新 `01-copilot/README.md`
2. 重写概览、交互界面、上下文和 Agent 章节
3. 重写定制、MCP、安全与排错章节
4. 迁移并精简讲师附录
5. 更新根目录入口和共享参考文档
6. 执行链接、术语、示例和 Markdown 校验

## 风险与控制

- **官方功能快速变化**：记录核验月份，减少对界面位置和默认值的依赖
- **重命名导致外部链接失效**：使用 `git mv` 保留历史，并在根目录和本期首页提供完整新导航
- **全面重构遗漏原有实用内容**：先建立原章节到新章节的迁移清单，再删除旧文件
- **参考手册再次变成长篇教程**：每章围绕任务入口和选择矩阵组织，背景解释保持最小充分
- **讲师附录与正文漂移**：附录只引用核心定义，并把操作预演列为分享前必检项
