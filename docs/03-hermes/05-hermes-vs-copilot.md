# Hermes 与 Copilot

## 本章解决什么

团队里已经有 VS Code Copilot，也可能开始使用 Hermes Agent。本章帮你区分：什么时候用 Copilot，什么时候用 Hermes，以及两者怎样配合。

## 一张表看懂区别

| | Copilot | Hermes |
| --- | --- | --- |
| **主要入口** | VS Code 编辑器 | 桌面应用、命令行、TUI、消息平台 |
| **更擅长** | 写代码、解释代码、改项目文件 | 执行多步任务、调用工具、处理文件和系统操作 |
| **典型用户** | 程序员、技术美术、写脚本的人 | 开发、技术美术、美术、建模和需要自动化的人 |
| **工作方式** | 在编辑器里辅助你思考和修改 | 像助理一样规划、执行、汇报 |
| **是否需要 VS Code** | 需要 | 不一定需要 |
| **是否能直接操作系统工具** | 受 VS Code / Copilot 工具范围限制 | 可以通过 Hermes 的工具系统执行命令、读写文件、调用浏览器等 |
| **最重要的人工责任** | 审查代码和方案 | 审查执行范围、文件变更和最终结果 |

## 用一个场景说明

假设你是 3D 建模同事，刚导出了一批角色素材，需要：

1. 按角色名整理 50 个 FBX 文件。
2. 为每个角色生成一个材质清单。
3. 把测试目录里的 PNG 贴图统一转成 JPG。

**用 Copilot：**

你可以在 VS Code 里让 Copilot 帮你写一段脚本、解释脚本、检查命令风险。它适合当“军师”和“脚本助手”。

**用 Hermes：**

你可以把目标说给 Hermes：

> “请先只检查 `D:/Project/export-test` 目录，列出会被处理的文件，不要修改。确认后再按角色名前缀分类，并生成材质清单。”

Hermes 更适合当“执行助理”。它会规划步骤、调用工具、给出结果；涉及修改文件时，你仍要审查和确认。

## 什么时候用 Copilot

| 场景 | 为什么用 Copilot |
| --- | --- |
| 你正在 VS Code 里写代码、脚本、Shader 或文档 | 它就在编辑器里，不用切换工具 |
| 你需要解释一段代码或报错 | 选中代码直接问，效率高 |
| 你想让 AI 帮你把需求整理成清晰指令 | Copilot 适合先把话说清楚 |
| 你要审查 Hermes 生成的脚本或命令 | Copilot 可以帮你指出潜在风险 |

## 什么时候用 Hermes

| 场景 | 为什么用 Hermes |
| --- | --- |
| 你要执行多步任务 | Hermes 会规划步骤并连续推进 |
| 你要处理电脑上的文件、目录、表格或报告 | Hermes 可以调用文件和终端工具 |
| 你不想自己写脚本 | 用自然语言描述目标即可 |
| 你希望 AI 记住偏好和项目约定 | Hermes 有 Memory 和 Skill 系统 |
| 你需要在聊天软件中触发任务 | Hermes Gateway 可连接 Telegram、Discord、Slack 等平台 |

## 两者怎么配合

核心原则：**Copilot 帮你想清楚，Hermes 帮你做下去。**

```text
你有一个任务
  ├─ 不知道怎么表达 → 先问 Copilot，让它帮你写成清晰指令
  ├─ 指令已经清楚 → 发给 Hermes，让它检查并执行
  └─ 执行结果不放心 → 把计划、命令或结果贴回 Copilot 辅助审查
```

推荐工作流：

1. **用 Copilot 写指令**：让它把口语需求改成“目标、路径、约束、验收标准”。
2. **用 Hermes 先检查**：要求 Hermes 先列出计划和将要处理的文件，不要立刻修改。
3. **你确认范围**：确认目录、命名规则、输出格式是否正确。
4. **让 Hermes 执行**：在测试目录先跑一遍。
5. **你抽查结果**：确认没问题后再迁移到正式目录。

## 进阶：用 Copilot 管 Hermes 的安装、启用、升级和异常处理

如果 Hermes 安装在 WSL 中，而你日常主要使用 VS Code，可以把 Copilot 当成“外部维护助手”：

| 环节 | Copilot 做什么 | Hermes 做什么 |
| --- | --- | --- |
| **安装** | 在 VS Code 连接本地 WSL 后，解释 WSL / Ubuntu / Hermes 安装命令，陪你一步步执行 | 被安装到 WSL 环境里 |
| **启用** | 帮你检查终端路径、PATH、端口和报错 | 通过 `hermes dashboard` 提供日常使用入口 |
| **升级** | 对源码版 Hermes，使用专门的升级 Agent 检查 git 状态、拉取更新、运行验证 | 不在当前 Hermes 会话里“自己更新自己” |
| **异常处理** | 根据终端日志补充检查命令、修改配置、复查结果 | 提供日志、状态和实际运行环境 |

这套做法的核心价值是：**Copilot 在 VS Code 里负责维护 Hermes，Hermes 负责日常 Agent 工作。** 两者分工清楚，出问题时也更容易定位。

> ⚠️ 如果你使用的是团队提供的 Desktop 安装包或普通安装器，不一定需要源码升级 Agent；升级方式以团队发布说明为准。

## 选型建议

| 你的角色 | 建议 |
| --- | --- |
| **纯美术 / 建模** | 先用 Copilot 辅助理解和安装 Hermes；日常文件整理、报告、批处理优先试 Hermes。 |
| **技术美术** | 两个都用：写脚本和审查命令用 Copilot，批量执行和流程自动化用 Hermes。 |
| **程序员 / 实习生** | Copilot 是代码主力；Hermes 适合跑测试、查资料、批量改文档、管理本地任务。 |
| **不确定自己属于哪类** | 先让 Copilot 帮你把任务说清楚，再让 Hermes 在测试目录里执行一次，看是否节省时间。 |

## ⚠️ 使用两者时你必须亲自做的事

| 环节 | 谁做 | 说明 |
| --- | --- | --- |
| 确定任务目标和验收标准 | ⚠️ 你 | 只有你知道“什么结果算合格” |
| 提供文件路径和项目规则 | ⚠️ 你 | AI 不知道你的文件实际放在哪里 |
| 管理 API 密钥和账号 | ⚠️ 你 | 不要把密钥发给任何 AI 聊天窗口 |
| 审查计划、命令和最终结果 | ⚠️ 你 | 批量操作后必须抽查 |
| 改写指令、解释报错 | 🤖 Copilot | 它适合帮你组织语言和分析信息 |
| 执行自动化任务 | 🤖 Hermes | 在你授权范围内调用工具完成 |
