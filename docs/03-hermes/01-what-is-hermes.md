# Hermes 是什么

## 本章解决什么

用最通俗的话讲清楚三件事：Hermes Agent 到底是什么、它能帮你做什么、它不能替你做什么。读完后，你可以判断自己是否需要使用它。

## 一句话说清楚

**Hermes Agent 是 Nous Research 推出的个人 AI Agent。**

你可以把它理解成一个“会使用电脑工具的 AI 助理”：你告诉它目标，它会先理解任务，再在你授权范围内调用终端、文件、浏览器、技能、记忆等工具，一步步推进任务。

> 普通 AI 聊天像一个**顾问**：你问问题，它给建议。
>
> Hermes 更像一个**执行助理**：你交代任务，它会规划、执行、汇报；遇到敏感操作时，需要你确认。

## Hermes 能做什么

对于美术、建模和技术美术同事，Hermes 更适合处理“需要动手执行”的工作。

| 场景 | 你可以让 Hermes 做什么 | 举例 | 分工 |
| --- | --- | --- | --- |
| 批量文件整理 | 搜索、分类、重命名、生成清单 | “把贴图按角色名分到不同文件夹” | 🤖 执行；⚠️ 规则由你定 |
| 文档与表格处理 | 读取资料、汇总、生成 Markdown/CSV | “统计每个模型文件的命名和大小” | 🤖 执行；⚠️ 结果你验收 |
| 项目自动化 | 运行命令、检查输出、连续排错 | “帮我检查这个目录里有没有缺失贴图” | 🤖 执行；⚠️ 是否修改由你确认 |
| 长流程任务 | 分阶段规划、记录过程、继续上下文 | “先整理素材，再生成报告，再列出风险” | 🤖 推进；⚠️ 目标和取舍由你定 |
| 跨会话协作 | 通过 Memory 记住偏好，通过 Skill 复用流程 | “以后默认把输出放到 output/” | 🤖 记住；⚠️ 记什么由你决定 |

## Hermes 由哪些部分组成

| 部分 | 大白话解释 | 你需要知道什么 |
| --- | --- | --- |
| **模型（Model）** | Hermes 背后的“大脑” | 可以通过 `hermes model` 或 `hermes setup` 选择和配置 |
| **工具（Tools）** | Hermes 可以使用的“手和脚” | 例如终端、文件读写、浏览器、图片分析等 |
| **CLI** | 在命令行里使用 Hermes | 适合会复制粘贴命令的同事 |
| **TUI** | 终端里的现代界面 | 用 `hermes --tui` 启动，比纯命令行更像一个键盘界面 |
| **桌面应用** | Windows/macOS 上的图形界面 | 适合不想长期面对命令行的同事 |
| **Gateway** | 连接 Telegram、Discord、Slack 等消息平台的网关 | 不是“模型添加器”，主要用于让 Hermes 出现在聊天软件里 |
| **Memory** | Hermes 的长期笔记 | 记住偏好、环境、项目约定；不要存密码和密钥 |
| **Skill** | 可复用的流程说明和能力包 | 让 Hermes 遇到特定任务时知道成熟做法 |

## Hermes 不能替你做什么

Hermes 很适合执行，但不能替你承担判断责任。

| 它不能替你做的事 | 为什么 |
| --- | --- |
| 判断最终美术效果是否合格 | 审美、项目标准和客户偏好需要人判断 |
| 决定是否覆盖、删除或批量修改正式文件 | 这类操作有风险，必须你确认 |
| 保管 API 密钥、密码、账号验证码 | 这些是敏感信息，不应交给任何 AI 记忆或聊天记录 |
| 保证所有输出 100% 正确 | AI 可能误解需求或遗漏边界，最终验收必须由你做 |
| 知道你没告诉它的项目规则 | 未提供的路径、命名规范、交付要求，它不会凭空知道 |

## 适合先从哪些任务开始

建议先从低风险任务练手：

1. 让 Hermes 读取一个测试目录，列出文件清单。
2. 让 Hermes 生成一份 Markdown 报告，不修改原文件。
3. 在复制出来的测试文件夹里尝试批量重命名或格式转换。
4. 确认结果正确后，再迁移到正式项目。

> ⚠️ 不建议第一次就让 Hermes 对正式素材目录做“删除、覆盖、批量移动”等操作。
